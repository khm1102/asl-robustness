## 0. 먼저 알아둘 것: 슬라이드와 구현이 다른 부분
슬라이드를 그대로 읽으면 교수가 구현과 다른 점을 짚을 수 있다. 미리 정리해 둘 것.

1. **알파벳**: 슬라이드는 6개(A, B, C, L, V, Y). 구현은 10개(A B D F I L U V W Y). **C는 구현에 없다.** 이유: 대체 데이터셋에서 정적이고 혼동 쌍(U/V 등)을 넣어 난이도를 올리려 10개를 골랐다. 슬라이드 기준으로 맞추려면 C 포함 6개로 재실험이 필요(소요 시간 짧음, 아직 안 함).
2. **데이터**: 슬라이드는 Kaggle ASL Alphabet(87,000장). 구현은 Kaggle 인증이 없어 HuggingFace `Marxulia/asl_sign_languages_alphabets_v03`(10,873장, 26클래스) 중 10개 알파벳 4,198장. 배경·피부톤이 다양한 대신 손 그림 15%, 라이선스 `[미확인]`.
3. **프레임워크**: 슬라이드는 TensorFlow/Keras. 구현은 Keras 3의 torch 백엔드(서버 CPU에 AVX가 없어 TensorFlow 실행 불가). Keras 코드라는 점은 같다.
4. **직접 촬영 테스트**: 슬라이드는 팀원 촬영(실험 1~4). 구현은 **아직 0장**. 환경 변화는 합성 변형(어둡게, 잡동사니, 이동, 크기, 회전)으로 대체했다. 웹 데모의 "내 촬영 평가" 탭으로 모을 수 있다.
5. **일정**: 슬라이드는 5주, 처음 받은 기획안 PDF는 3주. 어느 쪽이 맞는지 팀에서 맞출 것.
6. **발표 성격**: 원 기획안 문서에 "이번 발표는 결과 발표가 아니라 기획안 발표, 실험 결과나 정확도 수치는 아직 없다"고 적혀 있다. 결과를 보여 줄지 팀이 정해야 한다. 보여 준다면 "사전 실험(합성 변형)"이라고 명시할 것.

## 1. 알고 있어야 할 핵심 (10줄)
1. 연구 질문: 이미지를 직접 학습하는 CNN vs 손 관절 좌표 + 머신러닝(RF) 중 촬영 환경 변화에 어느 쪽이 강한가.
2. 입력이 다르다: CNN은 픽셀 전체(손+배경+조명), RF는 MediaPipe가 뽑은 21개 관절 좌표(x,y,z).
3. 좌표 정규화: 손목을 원점으로 옮기고 손바닥 크기(손목~중지 뿌리 거리)로 나눈다 → 손의 위치·크기에 둔감해진다.
4. 평가는 같은 테스트 이미지로, MediaPipe가 손을 못 찾은 경우도 오답으로 센다(end-to-end).
5. 지표: Accuracy, Confusion Matrix, Accuracy Drop(깨끗한 환경 대비 하락폭).
6. 사전 실험 결과(합성 변형, 사진 715장, 10개 알파벳): 깨끗한 이미지 RF 94.2% / CNN-plain 57.7% / CNN-aug 47.7%.
7. 어두운 조명(0.5배): RF 69.9%(−24.3%p), CNN-plain 11.0%(−46.6%p, 무작위 수준 10%).
8. 단, 더 어두워지면 RF도 무너진다: 손 검출률이 95.7%→34.4%(0.25배). **병목은 분류기가 아니라 손 검출.** 검출된 것만 보면 86.3%.
9. 거리·각도 특징(geom)이 좌표 그대로(63차원)보다 정확도 약 10%p 높음. 특징 설계의 효과.
10. 한계: 합성 변형, 소규모 데이터, CNN이 작고 64×64, RF는 사전학습된 MediaPipe 덕. "ML vs DL"이 아니라 "손 검출기 + 분류기 vs 처음부터 학습한 소형 CNN"의 비교.

## 2. 차별점 (다른 팀/단순 비교 대비)
- **환경 변화 강건성**을 목표로 삼음: 정확도 한 숫자가 아니라 Accuracy Drop으로 비교.
- **검출 실패까지 포함한 공정한 비교**: MediaPipe 실패를 오답 처리하고, 검출 성공만 본 수치도 병행(end-to-end vs detected-only).
- **CNN 대조군**: 증강 없는 CNN과 증강한 CNN(어둠·잡동사니·이동·크기)을 모두 평가. "CNN이 약한 건 증강을 안 해서"라는 반론을 차단.
- **통계적 검증**: 같은 샘플 쌍체 부트스트랩 95% CI, McNemar 검정, 3 시드.
- **데이터 품질 점검**: 근접 중복 해시 군집 → 군집 단위 분할(누수 방지), 손 그림 15% 분리, 중복 누수 측정(RF 무작위 vs 그룹 분할 차 −0.7%p로 누수 없음).
- **모든 가설과 반증 조건을 문서화**: 가설 7개, 지지/부분 기각 판정(예: "정규화하면 위치 변화에 거의 영향 없다"는 부분 기각).
- **웹 데모**: 웹캠 실시간 인식, 합성 환경 변화 적용, 수어 따라하기 모드(참고 그림 + 설명), 테스트셋 둘러보기.
- 전부 재현 가능(코드·문서·결과·데이터 릴리스; 새 클론에서 전처리·RF 결과 동일 확인).

## 3. 예상 질문과 답변

**Q1. 왜 알파벳 6개(A, B, C, L, V, Y)만 골랐나요? 전체 26개는?**
정적 손 모양이고 서로 뚜렷하게 구분되는 글자로 비교 실험에서 "환경 변화의 영향"만 보려고 했다. 26개로 늘리면 M/N/T처럼 원래 헷갈리는 글자 때문에 모델 차이가 아니라 글자 난이도가 결과를 지배한다. J, Z는 움직임이 필요해 제외. (구현에서는 U/V 같은 혼동 쌍을 넣어 10개로 확장했다 — 슬라이드와 다르므로 언급 시 주의.)

**Q2. 왜 Random Forest인가요? SVM이나 신경망(MLP)은요?**
관절 좌표는 63~288차원의 작은 표 형태 데이터라 트리 앙상블이 학습이 빠르고 해석 가능하며 하이퍼파라미터에 덜 민감하다. 보조로 Decision Tree를 넣어 "앙상블 효과"도 본다. SVM/kNN/MLP 비교는 해보지 않았다 `[미실시]`. 사전 실험에서 거리·각도 특징으로는 DT(96.2%)와 RF(98.5%, 검출 성공만) 차이가 2.3%p로 작았다 → 모델보다 특징이 더 중요하다는 해석.

**Q3. MediaPipe도 딥러닝인데, "CNN vs 머신러닝" 비교가 맞나요?**
정확한 지적이다. RF 쪽도 앞단에 사전학습된 딥러닝 손 검출기가 있다. 그래서 우리가 비교하는 건 "입력 표현(픽셀 vs 관절 좌표)과 파이프라인"이다. 결론도 "RF가 더 좋다"가 아니라 "손 관절이라는 구조화된 표현이 환경 변화에 덜 민감하지만 검출 단계가 새 병목이 된다"로 말한다. 이 한계는 보고서에 명시했다.

**Q4. Kaggle 데이터는 배경이 단순한데, 환경 변화 실험이 가능한가요?**
맞다. Kaggle 데이터는 사실상 단일 환경이라 CNN은 학습 데이터에서 99%가 나와도 환경이 바뀌면 크게 떨어질 수 있고, 이는 "구조적 약점"이 아니라 도메인 갭일 수 있다. 그래서 (1) 직접 촬영 테스트셋을 따로 두고, (2) 증강을 적용한 CNN도 함께 평가한다. (구현에서는 Kaggle 접근이 안 돼 배경이 다양한 대체 데이터를 썼다.)

**Q5. CNN에 data augmentation을 하면 환경 변화에 강해지지 않나요? 공정한가요?**
그렇다. 실제로 증강 CNN은 어두운 조명(0.5배)에서 11.0% → 31.8%, 잡동사니 배경에서 19.9% → 37.4%로 좋아졌다. 대가로 깨끗한 이미지 정확도가 57.7% → 47.7%로 떨어졌다. 다만 증강 종류가 테스트 변형과 같아 "처음 보는 환경"이 아니다 → 공정성 한계로 명시.

**Q6. CNN 정확도가 깨끗한 이미지에서도 57.7%로 낮은데, 그럼 비교가 의미 있나요?**
좋은 지적이다. 원인을 분리하지 못했다(데이터량 클래스당 약 250장, 64×64 축소, 작은 모델 8만 파라미터, 하이퍼파라미터 미탐색). 그래서 절대 정확도 대신 **깨끗한 환경 대비 하락폭**으로도 비교했고, 바닥(무작위 10%)에 닿으면 하락폭이 구조적으로 작아지는 문제도 같이 보고했다. 해상도 확대·전이학습 ablation은 후속 과제 `[미실시]`.

**Q7. 손 검출에 실패하면 어떻게 처리하나요?**
기획안 요구대로 인식 실패(오답)로 센다. 동시에 검출 성공 샘플만의 정확도도 따로 보고한다. 이렇게 보니 어두운 조명(0.25배)에서 RF는 검출률이 34.4%로 떨어져 end-to-end 29.7%, 검출된 것만 86.3%였다 → 손실의 대부분은 분류가 아니라 검출. 임계값(0.1/0.3/0.5)을 바꿔도 같은 경향이었다.

**Q8. 좌표 정규화는 어떻게 하나요? 왜 필요한가요?**
손목(0번)을 원점으로 이동하고, 손목~중지 뿌리 거리로 나눈다. 손이 화면 어디에 있든, 크게/작게 찍혀도 같은 좌표계가 된다. 사전 실험에서 정규화 전(raw) RF는 손 이동 시 22%p 하락했지만, 정규화(norm)는 4.8%p였다. 단 "거의 0"이라는 가설은 기각 — 완전 불변은 아니다(회전, 검출 품질 영향).

**Q9. Accuracy Drop을 가장 중요하게 본다고 했는데 문제는 없나요?**
하락폭은 기준 정확도가 높은 모델에 불리하고 바닥(무작위 수준)에 닿은 모델은 하락이 작아 보인다. 그래서 절대 정확도, 하락폭, 검출률을 같이 본다. 예: dark_0.25에서는 CNN이 이미 바닥이라 RF의 하락이 더 커 보인다.

**Q10. 직접 촬영 데이터는 몇 장, 누가, 어떤 조건으로 찍나요?**
계획: 팀원 4명이 알파벳별로 4가지 환경(밝음, 어두움, 복잡한 배경, 손 위치·크기 변화)에서 촬영. 표본이 적으면 우연 변동이 커서 환경·알파벳당 최소 수십 장을 목표로 한다. 현재는 0장이고 웹 데모의 저장 기능으로 모은다 `[미확정: 목표 장수 팀에서 합의 필요]`.

**Q11. 훈련·테스트가 같은 사람/같은 사진 아닌가요? 데이터 누수는요?**
근접 중복을 해시로 군집화해 군집 단위로 train/val/test를 나눴다. 무작위 분할과 비교하니 RF 정확도는 94.3%(그룹) vs 93.5%(무작위)로 차이가 없어 중복 누수는 작았다. 단 같은 촬영자 누수는 촬영자 ID가 없어 측정하지 못했다.

**Q12. 결과가 예상과 다르면(CNN이 더 좋으면) 어떻게 하나요?**
가설마다 반증 조건을 미리 적어 두었고, 결과가 달라도 지우지 않고 상태(지지/기각)만 바꾼다. 실제로 7개 중 일부는 부분 기각됐다(예: 증강 CNN이 잡동사니 배경에서 RF와 하락폭 차이가 사라짐).

**Q13. 실생활 적용 가능성은? 수어 알파벳 정확도가 서비스에 쓰일 수준인가요?**
아니다. 이 프로젝트는 정적 알파벳 10개, 합성 환경, 소규모 데이터의 비교 실험이다. 실제 수어는 단어·문장 수준의 동작(연속 동작), 표정, 양손이 필요해 훨씬 어렵다. 우리 결론은 "손 관절 표현이 조명·배경 변화에 상대적으로 덜 민감하다"는 방향성 정도.

**Q14. 실시간으로도 되나요?**
웹 데모로 구현했다. 브라우저 웹캠 → 서버에서 MediaPipe + RF + CNN 2종 추론, 한 프레임 약 0.1초(느린 서버 CPU 기준). 환경 변화를 켜면 서버가 변형을 적용하고 모델이 본 이미지를 보여 준다. 수어를 모르는 사람을 위해 단어를 보여 주고 참고 수어 그림을 따라 하게 하는 모드도 있다. 사람이 직접 장시간 써 본 검증은 아직 부족하다.

**Q15. 일정이 5주인데 지금 어디까지 했나요?**
(결과를 보여 줄 경우) 데이터 준비, 두 모델 구현과 학습, 합성 환경 변화 평가, 통계 검증, 웹 데모까지 끝났고, 팀원 직접 촬영 테스트와 CNN 개선 실험이 남았다. (기획안만 발표할 경우) 위 내용은 사전 실험으로 한 줄로만 언급.

## 4. 모르는 질문이 왔을 때
- "그 부분은 아직 실험하지 못했고(`전이학습`, `SVM 비교`, `실제 촬영`), 보고서의 한계/후속 과제에 적었습니다."라고 먼저 인정한다.
- 숫자를 물으면 사진 715장, 3시드 평균, 합성 변형 기준임을 같이 말한다. 합성 변형을 "실제 환경"이라고 말하지 말 것.
- "RF가 더 좋다"로 단정하지 말고 "이 조건에서 구조화된 표현이 덜 민감했고, 검출 단계가 새 병목"이라고 말한다.
