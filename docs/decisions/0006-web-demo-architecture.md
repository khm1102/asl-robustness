# 0006. 웹 데모 구조 (브랜치 `feat/web-demo`)

- 상태: 채택
- 요구: FastAPI 웹에서 웹캠으로 인식을 해 보고, 실험 결과를 육안으로 확인.
- 결정과 이유
  1. **브라우저에서 캡처, 서버에서 추론.** 서버에는 웹캠이 없고, AVX 없는 CPU에서 MediaPipe 0.10.14/torch CPU만 동작하므로 추론은 서버(Docker). 클라이언트는 `getUserMedia`로 정사각 크롭 256×256 JPEG를 WebSocket으로 보내고, 응답(관절·예측·지연)을 받은 뒤에만 다음 프레임을 보내 큐가 쌓이지 않게 함.
  2. **https(자체 서명).** `getUserMedia`는 https/localhost에서만 허용 → uvicorn에 자체 서명 인증서(SAN: 서버 IP). 브라우저 경고를 한 번 수락해야 함.
  3. **합성 변형을 라이브에 적용.** 서버가 프레임에 실험과 같은 `perturb` 변형(어둡게, 잡동사니 등)을 적용한 뒤 인식하고, 모델이 실제로 본 이미지를 돌려줘 시각 비교 가능. 실제 조명 변경 없이 강건성 재현.
  4. **MediaPipe는 static_image_mode=True(프레임마다 독립 검출).** 실험과 동일 설정. tracking 모드가 더 부드럽고 어두운 곳에서 유리할 수 있으나 실험 수치와 비교 불가가 되어 채택 안 함 `[tracking 모드 결과는 미측정]`.
  5. **테스트셋 둘러보기는 실험 산출물 그대로.** 변형 이미지는 `testsets.py`와 같은 시드·순서로 재생성(검증: 120장에서 검출 여부 100% 일치, 관절 좌표 최대 차 0.0), 예측은 저장된 시드 0 결과(`results/*preds*.npz`)를 사용 → 보고서 수치와 같은 모델의 출력.
  6. **라이브용 최종 모델은 별도 학습·저장**(`aslrob.train_final`, 시드 0, 그룹 분할 train). 실험 때 모델은 저장하지 않았음 → 라이브 예측은 실험 시드 0 모델과 동일 설정이나 동일 가중치임이 보장되지는 않음 `[미확인: 재학습 가중치 동일 여부]`(BN/증강 난수는 시드 고정).
  7. **직접 촬영 저장·채점**: NEXT.md의 외적 타당성 과제를 위해, 라이브 탭에서 정답과 환경 태그(밝음/어두움/복잡한 배경/손 위치 변화)와 함께 원본 프레임을 `data/captures/`에 저장하고 세 모델로 채점.
- 알려진 한계
  - 서버 CPU(2코어, AVX 없음) 기준 지연은 일반 PC보다 큼. 실제 FPS는 사용자 환경에서 측정해야 함.
  - 정사각 크롭이라 화면 밖/크롭 밖의 손은 인식되지 않음(UI에 가이드 사각형 표시).
  - 데이터가 정적 사진 10개 알파벳뿐이어서 손 모양 전환 중이나 다른 알파벳은 오인식이 정상.
